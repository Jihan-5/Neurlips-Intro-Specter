## Summary of findings

**(a) Pooled success rate.** Pooling raw successes/n across all 16 cells (sum of
`round(is_success * n)` and `round(bl_success * n)` over the 16 rows of
`outputs/real/tables/head_to_head.csv` where `baseline == "reflexion"`):
Intro-Specter = 730/866 = **84.30%**, Reflexion = 739/866 = **85.33%**. This
**does not match** the paper's claimed 87.0% vs 85.4% — the reproducible pooled
number for Intro-Specter is actually *below* Reflexion, not above it (a 1.0pp
loss, not a lead). Total paired n across the 16 cells is 866 (cell n's are 60
per cell except truthfulqa_real, which has 36 for llama-3.1-8b/llama-3.3-70b/
mistral-nemo-12b and 38 for qwen-2.5-7b — see per-cell table below).

**(b) Win/tie/loss at the cell level.** Comparing `is_success` vs `bl_success`
per cell (sign of `delta` in `head_to_head.csv`): **6 wins / 4 ties / 6
losses** for Intro-Specter vs Reflexion across the 16 cells. This does **not**
match the paper's claimed 8 wins / 7 ties / 1 NS loss — the real matrix has
noticeably more losses (6, not 1) and fewer ties (4, not 7).

**(c) Strict significant wins vs Reflexion.** Filtering to `holm_reject ==
True AND delta > 0` across the 16 cells: **zero cells** qualify. Every one of
the 16 Holm-adjusted p-values (`p_holm` column) is 1.0 (all raw McNemar
p-values are already ≥ 0.096, see `p_raw` column), so no cell shows a
statistically significant Intro-Specter win over Reflexion, let alone the
paper's claimed +6.7pp/p=.012 result on musique_real×mistral-nemo-12b (that
cell in fact shows Intro-Specter *losing* to Reflexion, Δ = −3.3pp, p_raw =
0.754, consistent with the discrepancy flagged in the task).

**Row-count discrepancy (111 vs. expected 112).** The 16×7 = 112-row
head_to_head matrix has only **111** rows because one (dataset, model,
baseline) cell is genuinely absent: **(longmemeval_real, qwen-2.5-7b, tot)**.
Root cause, traced in the source files:
- `outputs/real/longmemeval_real__qwen-2.5-7b/longmemeval_real__all__seed42__tot.jsonl`
  has only **4** lines (of an expected 60).
- `outputs/real/longmemeval_real__qwen-2.5-7b/longmemeval_real__all__skipped_errors.jsonl`
  has **56** records with `"method": "tot"` and `"error_class":
  "ProviderError"` (e.g. `"could not parse JSON from model output"` —
  qwen-2.5-7b's ToT prompting reliably failed to emit parseable JSON for this
  cell), accounting for the missing 56 of 60 examples.
- In `scripts/aggregate_real_benchmarks.py::head_to_head()`, the target
  (`intro_specter_llm`, n=60) and baseline (`tot`, n=4) runs are inner-joined
  on `(task_id, seed)` before the McNemar test; the merge yields only 4
  overlapping rows, and the function has a guard `if len(merged) < 5:
  continue` (line 123), which drops this cell entirely rather than reporting
  an underpowered result. This is confirmed by `outputs/real/tables/
  main_table.csv`, where the row for (longmemeval_real, qwen-2.5-7b) shows
  `tot_n = 4, tot_success = 0.25` alongside `intro_specter_llm_n = 60`. This
  is a genuine data-quality gap (model-specific ToT failure), not a script
  bug — the aggregate script is correctly declining to run an underpowered
  (n=4) paired test.
